# Offline spreadsheet export

`generateWorkbook(state: FinanceState, range?: DateRange): Promise<Uint8Array>` from `src/export` builds a real Office Open XML `.xlsx` ZIP, entirely on device. Runtime dependency is `fflate`, a pure JavaScript encoder. No filesystem, networking, Node Buffer, native SDK, font download, or external spreadsheet service is used by the generator. The platform integration saves/shares the returned bytes with XLSX MIME type `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`.

## Workbook contract

| Sheet | Meaning |
| --- | --- |
| Overview | Recorded income, spending and net, cached `SUMIF` formulas against Transactions, largest expense categories and report methodology. |
| Transactions | One row per active transaction in range, original IDs, parent/child/full category names, merchant, note, recurrence linkage, original ISO timestamps, numeric NGN and exact integer kobo, numeric UTC date. |
| Categories | Direct category allocations, each transaction counted once, share of recorded income. Percentages are blank when income is zero. |
| Recurring | Actual daily/weekly/monthly/yearly rule frequency, per-occurrence amount, next due, active/paused status, separately counted confirmed transactions in report range. No assumed or normalized payments. |
| Budget vs Actual | Current cycle from the configured start day using the same local-calendar domain functions as the app. Independent of report range. Parent-category actuals include descendants. Overlapping budget rows must not be summed. |

A supplied report range is `[start, end)`: start inclusive, end exclusive. Omitting the range exports all active recorded history. The workbook includes the exact range and generation timestamp. The current cycle is computed at generation time. Cash-flow balance means income minus spending in the report, not a bank balance. Transaction tombstones are excluded; the app's separate backup flow preserves full state.

## Correctness and safety

Amounts are validated and aggregated using safe integer kobo before conversion to Excel numeric NGN cells. Totals that exceed JavaScript safe integer bounds fail with an error. Formula cells include cached numeric results for readers that cannot recalculate; desktop Excel can recalculate on opening. The raw kobo column supports exact reconstruction within the app's safe integer bounds; spreadsheets retain approximately 15 significant decimal digits, so exceptionally large values should use the separate full-state JSON backup for exact interchange.

All user-provided text uses explicit `inlineStr` cells, including values beginning `=`, `+`, `-`, or `@`. Only application-authored formulas enter formula nodes. XML metacharacters are escaped and invalid XML scalar values removed. Invalid dates, impossible calendar dates, invalid amounts, duplicate record IDs and category cycles encountered in the report fail before bytes are shared. Orphaned category references remain in totals as “Unknown category.” Text exceeding Excel's 32,767-character cell limit and reports exceeding Excel's row limit fail rather than silently truncate.

`tests/export` reads generated bytes with ExcelJS, independently of the writer. Tests cover cached formulas, reconciliation, typed numeric/date cells, navigation and formatting structure, XML/Unicode safety, injection strings, empty data, category denominator behavior, recurrence confirmations, exclusive report boundaries, deleted records, cycle budgets and corrupt inputs.
